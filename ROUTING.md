# Repository Routing Policy

## Canonical Destinations

- `injammed/ITEM` receives ITEM work.
- `injammed/ABYS` receives ABYS work.
- `injammed/SYNTEL` receives protocol and interoperability work.

## ITEM Scope

Route to `injammed/ITEM` when the work concerns:

- ITEM
- Aeternum Immutablis / AETIMM
- ITEM vs TIME ontology
- Animentvm when expressed as artifact doctrine
- symbolic object continuity
- semantic object graphs
- ITEM Vault doctrine
- mythic-economic artifact systems
- AI-native provenance for symbolic assets
- canonical artifact records
- artifact schemas
- canon-vs-slop judgment standards

## ABYS Scope

Route to `injammed/ABYS` when the work concerns:

- ABYS
- deployable product infrastructure
- GPT to Codex execution loops
- autonomous incubation council outputs
- agent orchestration
- persistent operational memory
- workflow engines
- market/product intelligence
- simulation dashboards
- creator/product tools
- software architecture and implementation scaffolds

## SYNTEL Scope

Route to `injammed/SYNTEL` when the work concerns:

- protocol design
- agent communication standards
- inter-agent message schemas
- protocol experiments
- protocol runtime infrastructure

## Conflict Rule

If a task mentions ITEM and another repository:

1. Put symbolic continuity doctrine, ITEM object schemas, mythology, provenance, and economic framing in ITEM.
2. Put executable software infrastructure, build systems, Codex workflows, and product orchestration in ABYS.
3. Put protocol runtime, message exchange, and interoperability infrastructure in SYNTEL.
4. Cross-link rather than duplicate when possible.

## Product Leakage Rule

If a document primarily describes app UX, monetization, implementation tickets, deployment, user acquisition, business strategy, or workflow automation, then it routes to ABYS unless it directly defines an ITEM artifact, schema, provenance model, canon rule, or artifact display requirement.

## Containment Rule

If a file rewards unreviewed volume, aesthetic excess without structure, fake profundity, or low-signal generation, it routes to `archive/slatra-contained/` unless it can be compressed into a candidate record.

## Anti-Contamination Rule

Do not write ABYS execution infrastructure into ITEM unless explicitly requested.
Do not write ITEM symbolic canon into ABYS unless it is needed as product content, fixture data, or integration reference.
Do not write SYNTEL protocol runtime into ITEM unless it is represented as an ITEM artifact or schema reference.

## Mechanical Routing Test

Every file should answer:

1. What repository owns this?
2. What route state owns this?
3. What schema or doctrine controls this?
4. What future action does this enable?

Files that cannot answer those four questions are structural slop.
