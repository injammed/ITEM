# ITEM Canon-vs-Slop Selection Rubric

## Purpose

This rubric turns ITEM from an idea archive into an artifact-selection system. ITEM should preserve what can become durable object doctrine and reject material that only produces atmosphere.

## Scoring model

Score each proposed ITEM fragment from 0-2 in each category.

| Category | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Artifact definition | No concrete object | Object implied | Object named, bounded, and classed |
| Preservation function | Decorative only | Preserves a theme | Preserves value, memory, provenance, form, or rule |
| Anti-entropy logic | Claims permanence | Mentions durability | Names decay threat and maintenance/review mechanism |
| Canon utility | Cannot be reused | Useful as inspiration | Can become schema, canon record, candidate, example, or manufacture/render spec |
| Boundary clarity | Mixes artifact, execution, and protocol | Mostly ITEM with leakage | Clearly artifact doctrine only |
| Provenance | No origin or lineage | Partial origin | Explicit source, version, status, and custody path |

## Decision thresholds

- 10-12: promote into `/canon`, `/schemas`, `/examples`, or a finished `/docs` doctrine file.
- 7-9: keep as `/candidates` and assign a refinement task.
- 4-6: compress into a short provenance note or reroute to ABYS/SYNTEL if the main value is execution/protocol.
- 0-3: delete or archive in `/deprecated` only if historically useful.

## Hard fail conditions

A fragment fails immediately if it:

- Uses grand language but never defines the artifact.
- Claims permanence without custody, maintenance, entropy, decay, or versioning.
- Treats currency, unit, token, denomination, minted object, and governance as interchangeable.
- Makes ABYS do canon selection or makes SYNTEL carry mythic doctrine.
- Cannot answer what ABYS can build or what SYNTEL can transmit because the artifact exists.

## Upgrade pattern

Every salvageable ITEM fragment should be rewritten into this minimum artifact brief:

```md
# Artifact name

## Status
candidate | canon | deprecated

## Class
physical object | digital object | denomination | museum room | image grammar | narrative asset | schema | doctrine

## Preservation function
What does this artifact preserve that time would otherwise dissolve?

## Anti-entropy mechanism
What makes it more than decoration?

## Provenance
Where did it come from, what version is it, and what prior material does it replace?

## ABYS handoff
What can be built, rendered, tested, simulated, manufactured, or displayed?

## SYNTEL handoff
What structured payload, message, identity, receipt, or registry entry can transmit this artifact?
```

## Better configuration ruling

ITEM should now behave as the upstream canon source for durable artifacts. It does not chase implementation detail and does not define inter-agent protocol. Its higher capability comes from stricter compression: fewer slogans, more records.
