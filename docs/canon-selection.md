# ITEM Canon Selection

ITEM uses canon-vs-slop selection to convert symbolic material into durable artifact infrastructure.

## States

### Canon
Accepted material. Canon entries are durable enough to be referenced by other artifacts, product work, visual systems, economic units, or narrative systems.

### Candidate
Promising material awaiting review. Candidates may be emotionally or visually strong but still need structure, metadata, constraints, or implementation details.

### Refinement Required
Material with a valuable core but excessive ambiguity, repetition, or symbolic inflation. This state requires compression into an artifact record or deletion.

### Deprecated
Superseded material retained only for provenance. Deprecated material should not be treated as current doctrine.

### Deleted
Material that adds no durable value, cannot be implemented, and does not preserve useful provenance.

## Selection rubric

Each artifact is scored from 0 to 3 on four dimensions.

| Dimension | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| Durability | Momentary phrase | Interesting fragment | Reusable motif | Long-lived artifact |
| Specificity | Vague | Named but underspecified | Structured | Reproducible |
| Implementation value | No path | Possible path | Clear path | Ready for production/spec |
| Coherence | Disconnected | Loose connection | Strong connection | Core ITEM doctrine |

## Thresholds

- 10-12: canon
- 7-9: candidate
- 4-6: refinement required
- 1-3: deprecated or graveyard
- 0: delete

## Review rule

An ITEM entry should answer:

1. What is the artifact?
2. Why does it resist entropy?
3. What form can it take: physical, digital, visual, economic, narrative, or protocol-adjacent?
4. What exact fields, files, or specs would allow someone else to reproduce it?
5. Does this belong in ITEM, or should it route to ABYS or SYNTEL?
