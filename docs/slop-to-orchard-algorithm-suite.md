# SLOP TROUGH™ Slop-to-Orchard Algorithm Suite

## Status

ITEM product doctrine and algorithmic north star.

## Objective

Design a proprietary family of algorithms that converts overwhelming AI-native media abundance into entertainment, temporary cultural prominence, structured judgment, reusable artifact traits, durable lineages, and eventually canonical ITEM artifacts.

```txt
SLOP
→ FOAM
→ JUDGMENT
→ TRAITS
→ LINEAGES
→ ORCHARD
→ CANON
```

The system must not confuse popularity with quality, novelty with truth, or engagement with canon.

## Public / Proprietary Boundary

Public and auditable:

- artifact schemas
- provenance fields
- lifecycle states
- contributor rights
- published board definitions
- moderation rules
- user-facing explanations
- lineage records
- final canon decisions

Proprietary and access-controlled:

- ranking weights
- anti-gaming thresholds
- bot and collusion models
- duplicate and derivative detection ensembles
- novelty baselines
- clustering heuristics
- model prompts and evaluators
- calibration datasets
- internal quality labels
- fraud signals
- commercial recommendation models

Do not put secret scoring weights, private evaluation datasets, abuse heuristics, private user data, API credentials, or model keys in the public repository.

## Algorithm Family

### ST-01 — Slop Intake Normalizer

Converts every supported medium into a common artifact envelope.

Inputs may include:

- images
- video
- audio
- text
- code
- simulations
- games
- mathematical proofs
- datasets
- interfaces
- physical-object designs

Outputs:

```ts
interface ArtifactEnvelope {
  artifactId: string;
  mediaType: string;
  creatorId: string;
  provenance: ProvenanceRecord;
  contentHashes: string[];
  embeddings: Record<string, number[]>;
  declaredTools: string[];
  rightsState: string;
  safetyState: string;
  createdAt: string;
}
```

Purpose: make all slop comparable at the metadata and lifecycle level without pretending all media share one aesthetic score.

### ST-02 — Provenance Confidence Engine

Scores how well the artifact's origin story is supported.

Signals:

- declared model and tools
- prompt or workflow disclosure
- source-material disclosure
- edit history
- timestamps
- content hashes
- linked commits or run logs
- license evidence
- contributor agreement
- contradictions across revisions

Output:

```txt
unverified
self-declared
partially supported
strongly supported
verified
contested
```

This is not a plagiarism verdict. It is an evidence-strength assessment.

### ST-03 — Synthetic Similarity and Derivation Graph

Detects duplicates, near-duplicates, motif reuse, stylistic imitation, and likely derivative clusters across media.

It should distinguish:

- exact duplicate
- trivial variation
- shared template
- shared motif
- intentional remix
- convergent similarity
- uncertain relation

The system may flag evidence for review but must not automatically make legal conclusions.

### ST-04 — Foam Ranker

Selects the temporary visible cream layer from the larger trough.

Foam is not canon. It is the most culturally active, strange, funny, controversial, failed, remixed, or rapidly evolving safe material.

Candidate signals:

- velocity of human judgments
- diversity of reactions
- remix/fork activity
- novelty relative to recent uploads
- constructive-comment density
- cross-domain surprise
- curator spotlight
- verified failure value
- spam and collusion penalties
- creator concentration penalties

Output boards may include:

```txt
Foam Now
Fastest Rising
Best Failure
Most Derivative
Most Contextless
Strangest Useful Fragment
Most Remixed
```

The Foam Ranker must decay rapidly and provide deliberate stopping points. It should not maximize time spent at any cost.

### ST-05 — Slop Signature Classifier

Classifies why an artifact is slop.

Possible signatures:

- derivative repetition
- prompt keyword pileup
- incoherent composition
- empty spectacle
- false depth
- weak provenance
- accidental grotesqueness
- broken simulation
- unverified proof
- unmaintainable code
- interaction failure
- useful failed experiment

An artifact may have multiple signatures.

### ST-06 — Multi-Dimensional Judgment Engine

Keeps entertainment judgments separate from preservation judgments.

Public actions:

```txt
PRESERVE
REFINE
SLOP
```

Structured dimensions:

- novelty
- coherence
- emotional or entertainment impact
- provenance strength
- technical feasibility
- symbolic durability
- manufacturability
- mathematical validity
- reproducibility
- lineage value

No single opaque score should decide canon.

### ST-07 — Anti-Gaming and Collusion Shield

Protects rankings from:

- bot voting
- vote rings
- account farms
- coordinated brigading
- paid promotion
- creator self-amplification
- duplicate-upload flooding
- adversarial metadata
- stolen account activity

The system should reduce suspicious influence rather than publicly accusing users without human review.

### ST-08 — Trait Harvester

Extracts potentially useful fragments from complete artifacts.

Trait families:

- geometry
- material
- optics
- mechanism
- iconography
- denomination
- security
- interface
- narrative
- manufacturing
- proof technique
- simulation behavior
- code abstraction
- failure pattern

Every trait must preserve source and contributor lineage.

### ST-09 — Graft Compatibility Engine

Estimates whether traits from different artifacts can be productively combined.

It evaluates:

- functional compatibility
- aesthetic compatibility
- material compatibility
- dimensional constraints
- licensing compatibility
- contributor permissions
- contradiction risk
- novelty gain
- implementation cost

Output:

```txt
compatible
compatible after refinement
experimental graft
conflicting
legally blocked
insufficient evidence
```

### ST-10 — Orchard Clusterer

Builds stable design families from verified traits and refined artifacts.

Examples:

- diamond tesseracts
- optical security objects
- continuity stones
- mechanical cubes
- denomination studies
- civic memory systems
- black-hole megastructure concepts
- simulation families

Unlike Foam, Orchard clusters change slowly and require strong provenance.

### ST-11 — Cultivation Planner

Recommends the next action that increases an artifact's value:

- request stronger provenance
- isolate one trait
- run a simulation
- produce a counterexample
- revise geometry
- remove derivative material
- obtain rights
- ask an expert
- merge with a compatible lineage
- archive as a useful failure

The output must be actionable, not merely aesthetic criticism.

### ST-12 — Canon Candidate Selector

Identifies artifacts or synthesized lineages ready for formal canon review.

Minimum conditions:

- provenance threshold met
- rights and attribution resolved
- meaningful human judgment history
- curator review complete
- trait lineage visible
- technical claims labeled and reviewed
- no unresolved safety or fraud flags
- clear distinction between imagined, prototyped, functional, and production-ready states

This algorithm nominates. It does not unilaterally canonize.

### ST-13 — Immutablia Allocation Engine

Maps mature design families toward the finite 10,000-immutablia corpus.

It must optimize for portfolio diversity rather than only popularity:

- domain coverage
- material diversity
- geometric diversity
- civilizational function
- contributor diversity
- manufacturing feasibility
- historical significance
- symbolic durability
- redundancy reduction

The 10,000 are designed as a coherent corpus, not simply the 10,000 highest-scoring uploads.

### ST-14 — Contributor Lineage and Compensation Engine

Computes traceable influence for attribution and possible compensation.

It must never silently infer ownership from attention alone.

Inputs:

- verified traits
- declared licenses
- accepted grafts
- revision history
- curator decisions
- commercial-use consent
- final manufactured or licensed outputs

Outputs may support:

- attribution
- royalties
- fixed contributor payments
- licensing pools
- cooperative allocation

Any financial implementation requires separate legal review.

### ST-15 — Attention Thermostat

Uses attention science without making compulsion the objective.

Controls:

- feed velocity
- novelty rate
- notification frequency
- session stopping points
- repeated-content suppression
- exploration diversity
- contribution prompts
- cooldowns after heavy use

Primary commercial goal: entertaining return visits and contribution.

Primary constraint: do not sacrifice trust, contributor rights, or canon quality for raw session time.

## Core Composite Scores

The product may expose interpretable components while keeping exact production weights private.

### Foam Potential

```txt
cultural velocity
+ reaction diversity
+ novelty
+ remix activity
+ entertainment value
- spam
- collusion
- repetition
```

### Orchard Potential

```txt
trait value
+ provenance
+ refinement responsiveness
+ lineage usefulness
+ feasibility
+ symbolic durability
- rights uncertainty
- contradiction
- derivative dependence
```

### Canon Readiness

```txt
verified provenance
+ resolved rights
+ expert review
+ stable lineage
+ corpus usefulness
+ implementation evidence
- unresolved risk
```

These are multi-dimensional evaluations, not promises of objective truth.

## MVP Algorithm Order

Build in this sequence:

1. artifact envelope and media taxonomy
2. provenance confidence
3. duplicate/similarity detection
4. Foam ranking from real judgments
5. Slop signature classification
6. multi-dimensional scoring
7. anti-gaming controls
8. trait proposals
9. curator trait verification
10. Orchard clusters and lineage
11. cultivation recommendations
12. canon nomination

Do not begin with automated canon selection.

## Business Defensibility

The proprietary advantage should come from:

- a unique labeled corpus of slop, failure, refinement, and preservation
- cross-media provenance graphs
- human judgment calibration data
- verified trait lineages
- anti-gaming experience
- contributor-rights infrastructure
- longitudinal evidence of which traits later became valuable

The moat is not one mysterious formula.

The moat is the accumulated feedback loop:

```txt
more contributions
→ better labels
→ better ranking
→ better trait recovery
→ better outcomes
→ more valuable participation
```

## Guiding Law

> Slop fertilizes the orchard.

The algorithms exist to make that transformation measurable, entertaining, auditable, and commercially useful without pretending that abundance itself is value.
