# ITEM Boundary and Handoff Doctrine

## Role

ITEM is the upstream canon source for durable artifacts. It preserves selected symbolic, physical, digital, narrative, economic, and museum-grade objects as bounded records.

ITEM does not execute software workflows and does not define agent-to-agent protocol authority.

## Keep

Keep material that can become one of the following:

- canonical artifact record
- candidate artifact record
- artifact schema
- visual, physical, narrative, or museum specification
- denomination or minted-object doctrine
- anti-entropy preservation rule
- provenance/custody record
- canon-vs-slop review decision

## Delete, deprecate, or refactor

Flag material for deletion or refactor when it:

- uses grand language without naming a bounded artifact
- claims permanence without decay threat, maintenance rule, review cadence, or provenance
- treats currency, token, object, denomination, governance, and protocol as interchangeable
- imports ABYS execution workflow into ITEM doctrine
- imports SYNTEL agent protocol into ITEM canon
- cannot produce an ABYS build target or a SYNTEL transmittable payload

## Handoff contracts

### ITEM -> ABYS

A canon or candidate artifact must tell ABYS what can be built, rendered, tested, manufactured, displayed, or simulated.

### ITEM -> SYNTEL

A canon or candidate artifact must tell SYNTEL what structured payload, registry entry, identity reference, receipt attachment, or audit-visible object reference can transmit the artifact.

## Canon rule

ITEM gains power through compression. Fewer slogans. More durable records.
