# ITEM

ITEM is the repository for Aeternum Immutablis / AETIMM artifact doctrine: durable symbolic objects, anti-entropic preservation logic, canonical item records, narrative-economic artifacts, physical/digital object specifications, and artifact review governance.

ITEM is not the execution engine. It is the artifact canon.

## Repository Principle

This repository is not a general notebook.

It is a canon foundry.

Every file must eventually route to one of five states:

1. Canon
2. Candidate
3. Refinement
4. Archive
5. SLATRA Containment

Documents that cannot be routed are structural slop.

## Routing Rule

All ITEM-related work routes here when it concerns:

- Aeternum Immutablis / AETIMM doctrine
- ITEM vs TIME ontology
- canonical artifact records
- artifact schemas
- anti-entropy object logic
- visual / physical / narrative artifact specifications
- artifact review rubrics
- canon-vs-slop selection
- deprecated symbolic fragments retained for provenance

ABYS-related deployable software infrastructure belongs in `injammed/ABYS`.

SYNTEL-related agent-to-agent / machine-to-machine protocol infrastructure belongs in `injammed/SYNTEL`.

## Canon-vs-slop principle

ITEM material must survive selection pressure. Strong concepts become canonical artifacts, schemas, images, product specs, physical object specs, economic units, or narrative assets. Weak concepts are refined, deprecated, archived, or SLATRA-contained.

Grand language does not increase score. A file earns repository gravity only through structure, provenance, reproducibility, implementation surface, or durable aesthetic compression.

## Canon foundry structure

```txt
/canon
  /records             Schema-valid canonical and canon-candidate ITEM records
  /doctrine            Constitutional doctrine that controls future work
  /visuals             Accepted visual standards and canonical visual artifacts
  /economic-units      Canon-ready currency and denomination artifacts

/candidates
  /raw                 Unprocessed candidate inputs
  /refined             Edited candidate doctrine and specs
  /under-review        Candidate records awaiting judgment

/archive
  /deprecated          Superseded material retained for provenance
  /historical          Prior-state records and old doctrine snapshots
  /slatra-contained    High-slop-risk anti-examples and containment material

/docs
  /governance          Lifecycle, routing, source-of-truth, and repo rules
  /aesthetics          Interface and artifact-display standards
  /economics           Value formation and economic ontology
  /engineering         Implementation-facing standards
  /onboarding          Human-readable entry points

/schemas               Machine-readable artifact, contribution, and judgment schemas
/examples              Valid and invalid fixture records
```
