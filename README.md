# ITEM

ITEM is the repository for Aeternum Immutablis / AETIMM artifact doctrine: durable symbolic objects, anti-entropic preservation logic, canonical item records, narrative-economic artifacts, physical/digital object specifications, and artifact review governance.

ITEM is not the execution engine. It is the artifact canon.

## Routing Rule

All ITEM-related work routes here:

- Aeternum Immutablis / AETIMM doctrine
- ITEM vs TIME ontology
- canonical artifact records
- artifact schemas
- anti-entropy object logic
- visual / physical / narrative artifact specifications
- artifact review rubrics
- canon-vs-slop selection
- deprecated symbolic fragments retained for provenance

ABYS-related deployable software infrastructure belongs in `injammed/ABYS`.

SYNTEL-related agent-to-agent / machine-to-machine protocol infrastructure belongs in `injammed/SYNTEL`.

## Canon-vs-slop principle

ITEM material must survive selection pressure. Strong concepts become canonical artifacts, schemas, images, product specs, physical object specs, economic units, or narrative assets. Weak concepts are refined, deprecated, archived, or deleted.

## Initial repository structure

```txt
/docs              Doctrine, rubrics, artifact review guidance
/schemas           Machine-readable artifact schemas
/canon             Accepted canonical ITEM records
/candidates        Draft artifacts awaiting review
/deprecated        Retained provenance for weak or superseded material
/examples          Example artifact records
```

## Build direction

ITEM should become a disciplined artifact foundry: a place where symbolic material is compressed into durable records that can be implemented, manufactured, rendered, sold, displayed, simulated, or used by ABYS and SYNTEL without contaminating those repositories with mythic sprawl.
