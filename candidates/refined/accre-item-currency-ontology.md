# ACCRE–ITEM Currency Ontology

Status: Candidate / Refined  
Owner: ITEM  
Canonicality: Pending review

## Thesis

ITEM currency is not coin art, token branding, or decorative symbolic residue. It is the canonical artifact expression of ACCRE-interpreted value relations, rendered through the VMS triad.

## Core Principle

**ACCRE interprets value. ITEM mints it.**

## Semantic Engine

### VMS Triad

- Vacuo = Scarcity → Memory
- Mute = Memory → Exchange
- Singulus = Exchange → Scarcity

These are not merely names. They are the transformation logic underlying the currency system.

## Ontological Implication

Each currency artifact must answer:

1. What value state does it represent?
2. What transformation does it encode?
3. Why does it deserve artifact dignity?
4. How is it visually differentiated from adjacent denominations?

## Proposed Currency Families

### 1. Vacuo Family

Use:

- reserve class
- deep storage
- scarcity-indexed preservation
- non-circulatory or low-circulatory units

Visual grammar:

- black / gold
- dense seals
- restrained luminous core
- heavy archive geometry

### 2. Mute Family

Use:

- transfer class
- relay and exchange mediation
- signaling / transactional movement
- sub-denominational passage units

Visual grammar:

- silver / blue
- lighter pathways
- signal geometry
- networked structure

### 3. Singulus Family

Use:

- singular issuance
- minted event units
- ceremonial / canonical / historically fixed artifacts
- top-order declarations of exchange completion

Visual grammar:

- solar gold
- radiant core
- singular seal logic
- high-form ceremonial density

## Required Fields for Any Currency Candidate

- unit_name
- family_class: Vacuo / Mute / Singulus
- denomination_relation
- thesis
- use_case
- issuance_logic
- substrate
- visual_grammar
- anti_entropy_claim
- provenance
- veto_risks

## Admission Test

A candidate passes only if it is:

- mapped to VMS semantics
- distinguishable from adjacent units
- explicit about issuance logic
- readable at icon, card, and artifact scales
- plausible as both doctrine and object

## Rejection Triggers

Reject if:

- visually impressive but semantically empty
- pseudo-profound naming without ontology
- duplicate denomination logic
- fantasy-game framing without artifact seriousness
- “token” implies market / crypto launch rather than ontology

## North Star Statement

ITEM currency canon should become a coherent artifact family that can be:

- rendered
- archived
- simulated
- explained
- manufactured
- referenced by ABYS
- later encoded in SYNTEL metadata

## Current Verdict

Promising. Strong conceptual spine. Needs schema, example units, and render templates before canonization.
